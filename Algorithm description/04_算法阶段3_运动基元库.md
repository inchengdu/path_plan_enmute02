# 算法阶段 3：运动基元库

## 1. 阶段作用

根据最大转角 \(\beta_\theta\) 和基元长度范围，构造可用于离散 A* 搜索的运动基元库。每个基元包含整数端点位移、实际航向、物理长度、稠密输出点和完整碰撞覆盖。

## 2. 输入接口

### `PrimitiveStageInput`

| 字段 | 含义 |
|---|---|
| `beta_theta` | 最大实际转角 |
| `beta10` | 基元最短物理长度 |
| `beta14` | 基元最大物理长度 |
| `numeric_epsilon` | 数值容差 |
| `heading_refinement_max` | 航向加密次数上限 |

本阶段不依赖具体地图内容。

## 3. 算法流程

### 3.1 构造名义航向

初始航向数为：

\[
N_H=4\left\lceil\frac{\pi}{2\beta_\theta}\right\rceil.
\]

均匀生成一圈名义航向，使初始航向间隔不大于 \(\beta_\theta\)。

### 3.2 枚举名义长度并量化端点

1. 枚举覆盖 \([\beta_{10},\beta_{14}]\) 的名义长度。
2. 对每个名义航向和长度计算连续位移。
3. 对位移绝对值向上取整，再恢复正负号：
   \[
   Q_\uparrow(z)=\operatorname{sgn}(z)\lceil|z|\rceil.
   \]
4. 得到整数位移 \((d_x,d_y)\)。

量化的是相对位移，不是全局坐标；负数分量不能直接使用普通 `ceil`。

### 3.3 计算实际几何

根据量化位移重新计算：

\[
\phi_{\mathrm{actual}}=\operatorname{atan2}(d_y,d_x),
\qquad
L_{\mathrm{prim}}=\sqrt{d_x^2+d_y^2}.
\]

只保留满足 \(\beta_{10}\leq L_{\mathrm{prim}}\leq\beta_{14}\) 的基元。

### 3.4 构造两类离散几何

- `dense_offsets`：从基元起点到量化端点的有序数字直线，用于输出稠密路径。
- `supercover_offsets`：闭线段接触的全部栅格，用于碰撞检查。

数字直线不能代替 supercover 碰撞覆盖。

### 3.5 去重、航向加密与编号

1. 相同整数位移只保留一个基元。
2. 检查实际航向的最大循环间隔是否不超过 \(\beta_\theta\)。
3. 若量化造成航向空隙过大，则把名义航向数加倍并重建。
4. 按实际航向、长度和位移稳定排序并编号。

## 4. 输出接口

### `PrimitiveLibrary`

| 字段 | 含义 |
|---|---|
| `primitives` | 全部 `MotionPrimitive` 记录 |
| `heading_angles` | 去重后的实际航向集合 |
| `by_heading` | 按实际航向索引的基元列表 |
| `construction_parameters` | 构造使用的转角、长度和量化规则 |

### `MotionPrimitive`

| 字段 | 含义 |
|---|---|
| `primitive_id` | 稳定编号 |
| `displacement` | 整数量化位移 |
| `actual_heading_angle` | 由量化位移计算的实际航向 |
| `primitive_length` | 实际物理长度 |
| `dense_offsets` | 稠密输出点 |
| `supercover_offsets` | 完整碰撞覆盖 |
| `nominal_heading_angle` | 构造时的名义航向，仅用于追踪 |

## 5. 基本功能检查

- 每个基元末端等于其量化位移。
- 每个基元实际长度位于规定范围内。
- 实际航向由量化位移计算，而不是直接使用名义航向。
- 实际航向最大间隔不超过 \(\beta_\theta\)。
- 相同配置产生相同基元编号和内容。
