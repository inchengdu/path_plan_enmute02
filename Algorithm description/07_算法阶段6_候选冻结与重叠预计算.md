# 算法阶段 6：候选冻结与重叠预计算

## 1. 阶段作用

把所有 OD 的候选集合变成不可修改的搜索空间，并预先计算每条候选的道路占用和不同 OD 候选之间的重叠面积，使组合优化能够快速评价候选替换。

## 2. 输入接口

### `PrecomputeStageInput`

| 字段 | 含义 |
|---|---|
| `candidate_sets` | 阶段 5 输出的全部 `CandidateSet` |
| `map_size` | 地图边长 |
| `road_width` | \(\beta_3\) |

## 3. 算法流程

### 3.1 冻结候选

1. 确认每个 OD 至少有一条候选路径。
2. 为每条候选分配稳定候选编号。
3. 将全部候选集合设置为不可变。
4. 冻结后不允许添加、删除或修改候选坐标，也不再调用 A* 扩充候选。

### 3.2 生成道路掩码

对每条候选路径，以道路半径 \(\beta_3/2\) 把中心折线转换成二值道路占用：

\[
B_{rk}(c)=\mathbf1\!\left[d(z_c,\Gamma_{rk})\leq\frac{\beta_3}{2}\right].
\]

道路掩码可存为行主序压缩位集。

### 3.3 预计算候选对重叠

只对不同 OD 的候选计算：

\[
Q_{rk,sl}=|B_{rk}\cap B_{sl}|.
\]

矩阵对称，同一 OD 的候选不会同时被选，因此不需要进入组合目标。

### 3.4 保存候选静态指标

为每条候选保留：

- 物理长度；
- 道路位集；
- 几何哈希；
- 基元使用序列；
- 可选的软障碍候选指标。

## 4. 输出接口

### `FrozenCandidateSets`

与输入候选集合内容一致，但 `frozen=true`，后续阶段只读。

### `CandidatePrecompute`

| 字段 | 含义 |
|---|---|
| `road_masks[od][candidate]` | 各候选道路位集 |
| `overlap_Q` | 不同 OD 候选对重叠矩阵 |
| `physical_lengths` | 候选物理长度表 |
| `optional_soft_costs` | 可选候选软代价表 |

## 5. 基本功能检查

- 冻结后候选集合不能再被修改。
- 道路掩码使用 \(\beta_3/2\) 作为半径。
- 重叠矩阵非负且对称。
- 位集重叠数量与朴素布尔掩码交集数量一致。
- 每个预计算条目能通过 OD 和候选编号唯一访问。
