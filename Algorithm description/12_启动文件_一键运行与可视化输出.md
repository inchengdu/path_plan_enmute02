# 启动文件：一键运行与可视化输出

## 1. 文件作用

本文件定义整个路径规划算法的唯一启动入口。开发完成后，用户只需提供一份 TOML 配置并运行一次启动入口，程序就应按固定顺序完成：

1. 读取和标准化配置；
2. 生成地图与 OD；
3. 构造运动基元和稠密候选路径；
4. 完成多 OD 候选组合优化；
5. 完成控制点稀疏化和连续优化；
6. 全局重算最终结果；
7. 保存计算数据、运行记录和四张 PNG 图片。

启动文件只负责阶段编排、数据传递、输出管理和状态汇总。各阶段的算法实现仍放在对应模块中，启动文件不能复制阶段内部算法。

## 2. 开发目标

程序应提供一个唯一的公开启动函数或命令行入口。无论内部使用何种语言和模块组织，对外语义统一为：

### 输入接口 `LauncherInput`

| 字段 | 必需 | 含义 |
|---|---:|---|
| `config_path` | 是 | TOML 配置文件路径 |
| `output_root` | 是 | 本次运行结果的保存根目录 |
| `run_name` | 否 | 人工指定的运行名称；未提供时由时间和配置哈希生成 |
| `external_map_path` | 否 | 外部地图路径；未提供时随机生成地图 |
| `overwrite_policy` | 否 | 输出目录已存在时的处理方式，建议默认为拒绝覆盖 |

建议默认读取 `路径规划算法_超参数初始配置.toml`。所有可调整参数都从 TOML 读取，启动文件和阶段模块中不重复硬编码超参数。

### 输出接口 `PipelineRunResult`

| 字段 | 含义 |
|---|---|
| `run_id` | 本次运行唯一标识 |
| `status` | 完整成功、计算成功但图片不完整、或某阶段失败 |
| `completed_stages` | 已完成阶段编号 |
| `final_result` | 成功时返回阶段 10 的 `FinalResult` |
| `output_directory` | 本次运行输出目录 |
| `figure_paths` | 四张 PNG 的保存路径 |
| `failed_stage` | 失败阶段；成功时为空 |
| `failure_reason` | 简短失败原因；成功时为空 |

## 3. 一键执行顺序

启动入口必须严格按下表顺序调用各阶段。

| 顺序 | 调用内容 | 主要输入 | 主要输出 | 随后执行的动作 |
|---:|---|---|---|---|
| 0 | 创建运行目录和初始清单 | `LauncherInput` | 输出目录、初始 manifest | 记录运行开始状态 |
| 1 | 阶段 1：配置与随机流初始化 | TOML 配置 | `NormalizedConfig`、`RandomStreams` | 保存标准配置快照 |
| 2 | 阶段 2：地图生成与代价场 | 配置、地图随机流 | `GridMap` | 保存地图数据 |
| 3 | 阶段 3：运动基元库 | 转弯和长度参数 | `PrimitiveLibrary` | 保存基元摘要 |
| 4 | 阶段 4：OD 采样与基准路径 | 地图、基元库、OD 随机流 | `ODRecord[]` | 连续生成 PNG 1 和 PNG 2 |
| 5 | 阶段 5：稠密候选路径 | OD、地图、基元库 | `CandidateSet[]` | 保存候选摘要 |
| 6 | 阶段 6：候选冻结与预计算 | 候选集合、道路宽度 | 冻结候选、`CandidatePrecompute` | 保存重叠预计算摘要 |
| 7 | 阶段 7：多 OD 组合优化 | 冻结候选、预计算矩阵 | `CombinationResult`、选中稠密路径 | 生成 PNG 3 |
| 8 | 阶段 8：控制点稀疏化 | 选中稠密路径、地图 | `SparseControlPaths` | 保存稀疏控制路径 |
| 9 | 阶段 9：连续控制点优化 | 稀疏路径、地图、指标接口 | `ControlOptimizationResult` | 生成 PNG 4 |
| 10 | 阶段 10：最终重算与输出 | 最好网络、地图、配置 | `FinalResult` | 保存最终数据并结束运行 |

阶段 2 和阶段 3 在数据上彼此独立，但启动文件首版应按表中顺序串行调用，使日志和问题定位更清晰。阶段内部允许按各自文档要求并行处理。

## 4. 阶段数据传递

启动文件必须保存明确的阶段结果变量，并只把需要的数据传给下一阶段：

| 当前阶段输出 | 使用它的后续阶段 |
|---|---|
| `NormalizedConfig` | 所有阶段 |
| `RandomStreams` | 地图、OD、候选、组合和控制优化阶段 |
| `GridMap` | OD 搜索、候选生成、稀疏化、控制点优化、最终输出和全部图片 |
| `PrimitiveLibrary` | OD 基准 A* 和候选 A* |
| `ODRecord[]` | 候选生成、PNG 1、PNG 2 |
| `CandidateSet[]` | 候选冻结与重叠预计算 |
| `CandidatePrecompute` | 组合优化 |
| `CombinationResult` | 选取组合优化后的稠密路径、PNG 3 |
| `SparseControlPaths` | 连续控制点优化 |
| `ControlOptimizationResult.best_network` | PNG 4 和最终全局重算 |

启动文件不得通过读取前一阶段的临时全局变量取得数据，也不得在后续阶段重新生成已经确定的地图、OD、候选或随机种子。

## 5. 可视化公共接口

建议提供统一的保存接口 `SaveNetworkFigure`。启动文件向它传递地图、OD、可选路径集合、可选控制点集合、标题和保存路径。

该接口只负责生成和保存图片，不修改任何算法数据。

### 公共绘图规则

- 使用无界面的离屏绘图模式，支持服务器和批处理环境。
- 只保存 PNG，不调用 `show`，不弹出窗口。
- 保存完成后关闭图像对象，避免多次实验累积内存。
- 所有图片使用相同地图范围、坐标方向、长宽比例和背景图层。
- 地图坐标保持 `x` 向右、`y` 向上；如果底层数组显示方向相反，应在绘图层统一修正。
- 所有图片中，同一个 OD 始终使用相同颜色。
- 起点、终点、路径和控制点的图例在四张图片中保持一致。
- 建议输出正方形图片，默认 `dpi = 150`；地图坐标轴等比例显示。
- 图片标题至少包含 `run_id`、图像阶段和 OD 数量。
- 图片写入临时文件成功后再替换正式文件，避免中断时留下半张图片。

### 公共地图图层

由底层到上层建议为：

1. 地图自由区域：白色；
2. 原始障碍：深灰色；
3. 原始障碍之外的硬膨胀区：浅灰色；
4. 可选软障碍影响区：低透明度颜色，不应遮挡路径；
5. 路径、OD 标记和控制点。

如果同时显示原始障碍和硬膨胀区，图例必须区分二者。所有碰撞语义仍以硬障碍为准。

### OD 视觉规则

- 每个 OD 分配一个稳定颜色 `od_color[od_id]`。
- 起点使用圆形标记，终点使用叉号或星形标记。
- 标签使用 `O01`、`D01`、`O02`、`D02` 等固定格式。
- 标签位置可做小范围视觉偏移，但不能改变真实坐标。
- 路径数量较多时，颜色仍按 `od_id` 固定，不能在不同图片中重新分配。

## 6. PNG 1：地图与 OD 点

### 生成时机

阶段 4 已完成全部 OD 接受并固定编号之后立即生成。

### 文件名

`figures/01_map_and_od.png`

### 输入

| 输入 | 内容 |
|---|---|
| `grid_map` | 原始障碍、硬障碍和地图范围 |
| `od_records` | 每个 OD 的起点、终点和编号 |
| `run_id` | 图片标题和追踪信息 |

### 绘图内容

- 完整地图；
- 原始障碍和硬膨胀区；
- 全部 OD 起点和终点；
- OD 标签和颜色图例；
- 不绘制任何路径。

### 作用

直观确认地图、障碍密度、OD 左右分布和端点净空是否符合实验设计。

## 7. PNG 2：基准路径网络

### 生成时机

与 PNG 1 连续生成。阶段 4 的每个 `ODRecord` 已经包含第一条基准路径，无需再次运行 A*。

### 文件名

`figures/02_baseline_path_network.png`

### 输入

| 输入 | 内容 |
|---|---|
| `grid_map` | 地图背景 |
| `od_records` | OD 及每个 OD 的 `baseline_path` |
| `run_id` | 图片标题和追踪信息 |

### 绘图内容

- 与 PNG 1 完全相同的地图和 OD 图层；
- 每个 OD 的第一条路径 `baseline_path`；
- 路径中心线按对应 OD 颜色绘制；
- 可选显示道路宽度，但默认只画中心线，使十条路径仍清晰可见。

### 作用

展示所有 OD 独立选择基准最短路径时形成的初始网络，用作组合优化和控制点优化的视觉比较基准。

## 8. PNG 3：组合优化后的稠密路径网络

### 生成时机

阶段 7 返回 `CombinationResult` 并取得每个 OD 选中的稠密候选后生成。

### 文件名

`figures/03_combination_optimized_network.png`

### 输入

| 输入 | 内容 |
|---|---|
| `grid_map` | 地图背景 |
| `od_records` | OD 起终点和稳定颜色 |
| `selected_dense_paths` | 组合优化为每个 OD 选择的稠密路径 |
| `combination_result` | 初始与最终组合重叠指标 |

### 绘图内容

- 地图、硬障碍和 OD 标记；
- 组合优化选中的全部稠密路径；
- 各路径按固定 OD 颜色绘制；
- 标题或图注包含组合优化前、后的重叠面积；
- 可选以半透明红色显示不同道路掩码的重叠区域。

### 作用

展示只在冻结候选中进行路径替换后，网络重叠相对基准网络发生的变化。

## 9. PNG 4：控制点优化后的最终路径网络

### 生成时机

阶段 9 完成并返回 `best_network` 后生成。绘制对象必须是 best-so-far 合法网络，不能绘制最后一次未通过约束的临时状态。

### 文件名

`figures/04_control_point_optimized_network.png`

### 输入

| 输入 | 内容 |
|---|---|
| `grid_map` | 地图背景 |
| `od_records` | OD 标记和固定颜色 |
| `best_network.control_paths` | 最终合法控制折线 |
| `best_network.true_metrics` | 优化后的 \(L,D,A,R,J_{\mathrm{true}}\) |

### 绘图内容

- 地图、硬障碍和全部 OD 标记；
- 每个 OD 的最终控制折线；
- 控制线段使用对应 OD 颜色；
- 内部控制点使用小圆点，起终点使用统一 OD 标记；
- 可选以更大的空心圆突出真实转弯控制点；
- 可选以半透明红色显示最终重叠区域；
- 标题或图注包含最终主要指标和完成优化轮数。

### 作用

展示连续控制点调整后的最终道路网络，并直观检查控制点分布、转弯形态、障碍净空和路径分离结果。

## 10. 输出目录结构

每次运行使用独立目录，建议结构如下：

```text
output_root/
  run_id/
    config/
      input_config.toml
      normalized_config.json
    data/
      map_metadata.json
      od_records.json
      candidate_sets.json
      combination_result.json
      sparse_control_paths.json
      final_control_paths.json
      final_metrics.json
    traces/
      candidate_attempts.jsonl
      combination_trace.jsonl
      control_optimization_trace.jsonl
    figures/
      01_map_and_od.png
      02_baseline_path_network.png
      03_combination_optimized_network.png
      04_control_point_optimized_network.png
    run_manifest.json
    validation_summary.json
    runtime_profile.json
```

运行目录创建后，不允许静默覆盖另一次实验结果。若需要覆盖或恢复运行，必须由 `overwrite_policy` 明确指定。

## 11. 运行状态与失败处理

### 计算阶段失败

如果任一计算阶段失败：

1. 停止调用依赖该结果的后续计算阶段；
2. 保留已经成功生成的数据和图片；
3. 在 `run_manifest.json` 中写入失败阶段、原因和已完成阶段；
4. 返回失败的 `PipelineRunResult`；
5. 不用新随机数自动重新开始整次实验。

### 图片生成失败

图片是实验交付物，但不应使已经完成的算法计算失效：

1. 记录失败的图片名称和原因；
2. 继续后续算法计算；
3. 最终计算成功但图片缺失时，状态记为 `COMPUTE_SUCCESS_VISUALIZATION_PARTIAL`；
4. 保留绘图所需的阶段数据，使图片能够单独补生成；
5. 不为补图重新运行地图、A*、组合搜索或控制点优化。

### 最终成功条件

只有以下内容都存在时，状态才为完整 `SUCCESS`：

- 阶段 1 至阶段 10 全部成功；
- 最终路径通过阶段 10 的基本功能检查；
- 四张指定 PNG 均成功保存；
- `run_manifest.json` 和最终结果文件成功写入。

## 12. 运行清单更新

启动文件负责维护唯一的 `run_manifest.json`。每个阶段开始和结束时更新：

| 字段 | 含义 |
|---|---|
| `run_id` | 运行唯一标识 |
| `config_hash` | 标准配置哈希 |
| `status` | 当前总状态 |
| `current_stage` | 当前阶段 |
| `completed_stages` | 已完成阶段 |
| `stage_start_time` | 各阶段开始时间 |
| `stage_end_time` | 各阶段结束时间 |
| `stage_stop_reason` | 各阶段停止原因 |
| `figure_status` | 四张 PNG 的状态和相对路径 |
| `final_metrics` | 成功时的最终指标摘要 |

启动文件只记录阶段级信息；候选尝试、组合迭代和控制点移动的详细日志仍写入各自 trace 文件。

## 13. 启动文件的基本功能检查

开发完成后，只需确认以下功能能够实现：

- 一次启动能够按固定顺序调用阶段 1 至阶段 10；
- TOML 配置只读取一次，标准配置传递到全部阶段；
- 同一次运行只生成一套地图、OD 和随机流；
- 各阶段输出能够正确传入下一阶段；
- 阶段 4 后保存地图与 OD PNG、基准路径网络 PNG；
- 阶段 7 后保存组合优化网络 PNG；
- 阶段 9 后保存最终控制点网络 PNG；
- 绘图过程不调用 `show`，并在保存后释放图像资源；
- 四张图片中的地图范围、OD 颜色和坐标方向一致；
- 阶段失败时不会继续调用缺少输入的后续阶段；
- 完整成功时能够返回 `FinalResult` 和全部输出路径。

## 14. 开发时的模块边界

启动文件可以调用但不实现以下模块：

| 模块 | 职责 |
|---|---|
| `config` | TOML 读取、标准化和派生参数 |
| `map` | 地图、硬障碍、距离场和软代价场 |
| `motion` | 运动基元库 |
| `search` | 基准 A* 和候选 A* |
| `combination` | 候选冻结、重叠预计算和组合搜索 |
| `sparsify` | 控制点稀疏化 |
| `optimize` | 连续控制点优化 |
| `validation` | 最终功能检查和全局重算 |
| `visualization` | 四类 PNG 的离屏绘制与保存 |
| `io` | 目录、清单、数据和日志输出 |

启动文件本身只承担：调用、传参、接收结果、保存阶段状态和决定是否继续。
