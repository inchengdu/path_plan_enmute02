# 算法阶段 10：最终重算与输出

## 1. 阶段作用

从连续优化得到的 best-so-far 几何重新构造全部网络数据，不依赖优化过程的增量缓存，生成最终路径、指标、运行记录和简明功能检查结果。

## 2. 输入接口

### `FinalizationInput`

| 字段 | 含义 |
|---|---|
| `best_network` | 阶段 9 输出的最好合法网络 |
| `grid_map` | 地图、硬障碍和软代价场 |
| `config` | 完整标准配置 |
| `metric_provider` | 正式 \(D\) 和 \(R\) 计算接口 |
| `stage_reports` | 前面各阶段必要过程记录 |

## 3. 算法流程

### 3.1 从几何重建网络

1. 读取 best 网络的控制点坐标。
2. 重新生成每条控制折线和道路掩码。
3. 从全部道路掩码重新计算 `occupancy_count`。
4. 重新计算 \(L,D,A,R,J_{\mathrm{true}}\)。
5. 重新提取最终冲突组件。

### 3.2 检查最终路径功能

对每条路径确认：

- OD、起点和终点正确；
- 坐标有限并位于地图内；
- 线段无硬碰撞且非零；
- 相邻控制点距离不超过 \(\beta_{12}\)；
- 真实转弯角不超过 \(\beta_\theta\)；
- 真实转弯之间的沿路径距离不小于 \(\beta_{10}\)。

最终阶段不再检查 \(\beta_{11}\)、\(\beta_{13}\) 或 1.2 倍基准长度限制，因为它们分别属于稀疏初始化、稀疏近似和候选接纳阶段。

### 3.3 核对重叠结果

分别计算：

\[
A_{\mathrm{pair}}=\sum_{r<s}|B_r\cap B_s|,
\]

\[
A_{\mathrm{count}}=\sum_c\binom{n(c)}2.
\]

两者应一致。该检查确认最终道路掩码和占用计数功能正确。

### 3.4 整理输出

输出内容按用途分组：

- 运行配置和随机种子；
- 地图和 OD 记录；
- 候选与组合结果；
- 稀疏控制路径；
- 连续优化过程摘要；
- 最终控制路径；
- 最终指标；
- 简明功能检查报告；
- 运行时间和资源统计。

## 4. 输出接口

### `FinalResult`

| 字段 | 含义 |
|---|---|
| `status` | `SUCCESS` 或错误状态 |
| `final_control_paths` | 各 OD 最终控制点路径 |
| `final_metrics` | \(L,D,A,R,J_{\mathrm{true}}\) |
| `conflict_components` | 最终重叠区域 |
| `validation_summary` | 基本功能检查结果 |
| `run_manifest` | 配置、种子、阶段状态和停止原因 |

### 建议输出文件

| 文件 | 内容 |
|---|---|
| `run_manifest.json` | 配置、种子和阶段状态 |
| `map_metadata.json` | 地图与障碍信息 |
| `od_records.json` | OD 和基准路径信息 |
| `candidate_sets.json` | 冻结候选摘要 |
| `combination_result.json` | 多 OD 选择结果 |
| `sparse_control_paths.json` | 稀疏化输出 |
| `control_optimization_trace.jsonl` | 控制优化必要过程记录 |
| `final_control_paths.json` | 最终路径 |
| `final_metrics.json` | 最终指标 |
| `validation_summary.json` | 简明功能检查结果 |

## 5. 基本功能检查

- 全部最终路径可从起点到达终点且无碰撞。
- 转角、转弯间隔和控制点最大间距满足约束。
- 两种重叠计算得到相同结果。
- 最终指标从几何重新计算，不直接复用旧缓存。
- 输出包含复现实验所需的配置、种子和停止原因。
