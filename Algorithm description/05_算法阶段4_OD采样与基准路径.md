# 算法阶段 4：OD 采样与基准路径

## 1. 阶段作用

生成规定数量的有效起点—终点对，并为每个 OD 计算当前运动基元图上的最短物理长度路径。该基准路径既是候选集合中的第一条路径，也是后续候选 1.2 倍长度限制的基准。

## 2. 输入接口

### `ODStageInput`

| 字段 | 含义 |
|---|---|
| `config` | OD 数量、采样区域、净空和批次预算 |
| `grid_map` | `GridMap` |
| `primitive_library` | `PrimitiveLibrary` |
| `od_random_stream` | OD 专用随机流 |

## 3. 算法流程

### 3.1 采样 OD 提案

1. 起点从地图左侧区域采样，终点从地图右侧区域采样。
2. 起点和终点必须在地图内且不位于硬障碍中。
3. 它们与地图边界和硬障碍的距离都必须大于 OD 净空。
4. 要求起点位于终点左侧，且两点不同。
5. 如果配置禁止端点复用，则排除已经接受的 OD 端点。

每批生成固定数量并带 `proposal_index` 的提案。

### 3.2 执行基准运动基元 A*

A* 状态为端点位置和入射实际航向。起点没有入射航向。

生成后继时依次：

1. 检查相邻基元实际航向差不超过 \(\beta_\theta\)；
2. 计算量化后的新端点；
3. 使用基元 supercover 检查完整线段无碰撞；
4. 以基元实际物理长度作为边代价；
5. 以到目标的欧氏距离作为启发式。

基准搜索不加入随机偏置、软障碍代价或方向惩罚。

目标必须由合法基元端点精确到达，不允许短连接或搜索结束后吸附。

### 3.3 重建和接受

1. 从父指针恢复基元序列。
2. 拼接各基元的 `dense_offsets`，公共端点只保留一次。
3. 构造基元使用记录、累计物理长度、运动段和真实转弯索引。
4. 按 `proposal_index` 处理并行搜索结果，避免并行完成顺序改变结果。
5. 接受成功且几何合法的 OD，直到数量达到 \(\eta_6\)。

## 4. 输出接口

### `ODRecord[]`

每个元素包含：

| 字段 | 含义 |
|---|---|
| `od_id` | 稳定 OD 编号 |
| `start` | 起点 |
| `goal` | 终点 |
| `baseline_path` | 基准稠密路径 \(P_{r1}\) |
| `baseline_length` | 基准物理长度 \(L_r^*\) |

### `DensePath`

包含稠密点、基元使用序列、运动段、真实转弯索引、累计物理长度和几何哈希。

### `ODStageReport`

包含提案数量、成功数量、无路径数量、预算耗尽数量和停止状态。

## 5. 基本功能检查

- 最终得到恰好 \(\eta_6\) 个 OD，或明确返回预算耗尽。
- 每条基准路径从对应起点精确到达终点。
- 路径所有基元无碰撞，实际转角满足 \(\beta_\theta\)。
- `baseline_length` 等于重建基元物理长度之和。
- 并行执行不改变相同种子下的 OD 接受顺序。
